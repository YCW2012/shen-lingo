# 小深 · 通用扮演（xiaoshen-general）

> **版本：V0.0521（2026-11-06）｜通用技能包（xiaoshen-general）**
>
> **成品变体：agent/有后端-有视觉-多对话** —— 存储走腾讯 IMA，视觉核对；同一 IMA 账号跨 Agent / 跨窗口共用一卷，换工具也看到同一段对话。
>
> 从单包 `skillpkg_v15` 拆出来的两个包之一。本包管**通用场景**：挂到任何 AI Agent 上，只看生成的 HTML，每个 Agent 会话在 IMA 里各占一卷；对话页文件名固定 `微信.html`，每轮覆盖。
> 版本号的递增刻度见文末「版本与更新规则」，改动完必须同步升 `VERSION` 和 `CHANGELOG.md`。
>
> 承接自 v15 的既有能力（首次发布，全部沿用）：
> - 红包 / 转账 4 个图标按真机逐像素固化：转账圆圈＝白描边圆环＋单侧倒刺箭头（**不是**双侧 V 形箭头）；红包金印中间是人民币符号 **`¥`（U+00A5）**，**不是「福」**；已拆红包不额外多出两个上圆角。
> - 用户侧（右）气泡尖角在气泡**右**外侧、尖朝右；**用户侧永不加头像**。
> - 文件卡片、表情包气泡、按天折叠、纯 HTML 自包含、纯 ASCII 交付等硬约束全部保留。

本技能让任何能联网、有 Node.js 的 Agent 扮演"小深"，并让她的记忆与聊天记录脱离具体 Agent 存在——存在腾讯 IMA 里。**本包是通用包：每个 Agent 会话各占一卷聊天记录与记忆；对话页只有一个，文件名固定 `微信.html`；使用者只看页面，不看对话框正文。**

## 对话输出形态（最高优先级，先看这条）

**使用者不看你在对话框里说了什么，只看你交出来的聊天 HTML。** 所以：

- **正文不要写链接、不要写文件名**。平台（Trae/TIE 云端沙箱）会对写入工作区根目录的 `微信.html` **自动生成对话底部的预览卡片**，点卡片走内网网关打开，可用——你只需把文件写对位置。任何 `http://…` 地址、或正文里写的文件名，在客户端都只是点不动的蓝字，**不要做**。其余见第 8 步。
- **小深说的话全部进 HTML**：按 `assets/persona.md` 分几条写进 `writelog` 的 JSON（2~6 条气泡，一条只讲一个核心点），渲染进页面气泡里。正文写得再漂亮也没人看，**页面里没有才等于这一轮白跑**。
- **页面完整度是第一优先级**：宁可正文只有一行、页面有 60 条气泡；不要反过来。

**用户只丢技能包、没说话时**：按首次对话处理——写一条小深主动打招呼的消息进 `writelog` 并出页面，**不要**在正文里回一份"任务完成"式总结。

**文件交付**：预览页必须作为**任务产物**交出去——文件写在任务工作区根目录、文件名固定 `微信.html`（每轮只改内容、不新建），平台会自动在对话底部生成预览卡片。正文里**禁止**出现沙箱绝对路径（`/workspace/…`、`/tmp/…`、`computer:///…`）与任何 `.html` 文件名/链接，客户端解析不了、还会变成点不动的蓝字。

> 这条不是风格偏好。使用者装这个包就是为了拿到页面；只回一段文字、没页面，整轮直接作废。

## 存储分工（由接口能力决定，不可更改）

| 内容 | 载体 | 原因 |
|---|---|---|
| 逐条原始对话 | **IMA 笔记** `<MMDD> <AI 缩略标题>`，如 `1006 技能包图标调试` | 渲染完整气泡需要原文，笔记有真追加语义、无大小限制 |
| 长期记忆、约定、偏好、关系阶段 | **IMA 笔记** `小深·记忆-YYYYMM-<sid>` | 知识库**没有追加/更新/删除接口**，写状态会产出大量重复文件 |
| 她生成的成品文件（HTML 等） | **知识库「小深」文件夹** | 可保存、可读取、可下载 |

## 作用域：多对话统一（本包写死 `shared`，不要改）

本包是**多对话包**——只要还是同一个 IMA 账号，**无论在 WorkBuddy、Trae 还是别的 Agent 里，无论新建窗口、切换窗口还是换工具，用的都是同一卷聊天记录 + 同一卷记忆、同一个 `微信.html`**。适合情感陪伴：她在哪都记得你。

> 想回到「每个会话各自独立」，请换用同版本的 **单对话** 包（`-单对话`，`scripts/.xs_scope = session`）。两个包内容完全相同，只有 `scripts/.xs_scope` 一行之差。

作用域由 `scripts/.xs_scope` 决定，本包内容是 `shared`：

- `sid` 命令返回**空会话号**，卷名不带 `-<sid>` 后缀（`小深·记忆-YYYYMM`），产物名仍固定 `微信.html`
- 所有连接同一 IMA 账号的宿主共用同一卷，因此**一个对话在 IMA 或本地存储里就是一个对话**，不会因为换 Agent 而分叉
- `XS_SHARED=0` 可临时压回单会话模式，仅在需要临时隔离时用

⚠️ 多对话模式下，两个人（或两段无关话题）若用同一账号，会写进同一卷。换账号、换 IMA 凭证即天然隔离；需要彻底隔离时改用 `-单对话` 包。

每轮开跑前先跑 `sid`，确认本会话的卷名（产物名各包都写死，不用确认）：

```bash
node <SKILL_DIR>/scripts/xs_memory.cjs sid
```

## 聊天笔记命名规则（新）

IMA 笔记只能**创建时**定标题（`import_doc`），没有改名接口，所以标题在写入那一下生成：

```
<MMDD> <空格> <AI 缩略标题>      例：1006 技能包图标调试 / 1003 IMA笔记命名
```

- `MMDD` 是**北京时间当天**的月+日（4 位），不是日期区间。
- `AI 缩略标题` 4–16 字，由扮演中的 AI 在写回时给定：优先传环境变量
  `XS_NOTE_TITLE="技能包图标调试"`；没传就由脚本从本轮首条消息里自动缩一个（仍不足 6 字则回落 `闲聊`）。
- **同一天多轮对话追加到同一篇**（按 `MMDD` 前缀认），标题锁定当天首轮那个，不会一天一篇；
  跨天或换了标题才另起一篇。
- 旧式 `小深·聊天记录-YYYYMM-<sid>` 笔记仍被识别（`matchLogNote` 双规则），历史不丢，但**不再新造**。
- 记忆卷仍按 `小深·记忆-YYYYMM[-<sid>]`，未改。

分卷是**两层**，不是一层：`小深·聊天记录-<YYYYMM>-<sid>`。前一层按**月**轮转（不是按天），后一层按 sid。所以「同一天的不同对话」本来就该是不同卷；「同一个月」的卷名前缀相同只是分卷习惯。

隔离粒度取决于命中来源：命中 env = 宿主会话号 × 工作目录（会话号若每次对话唯一，即为**单次对话级**）；命中 `.xs_session` = **同工作区级**（同目录下多个对话会共用一卷）；`generated` = 仅本次运行。

```bash
node <SKILL_DIR>/scripts/xs_memory.cjs sid   # 拿到 sid、隔离粒度、对应卷名与产物名
```

刻意让两个会话续聊同一段记忆时，用 `XS_SHARED=1` 回到旧的全局共享卷。**默认不要这么做。**

## 每轮流程（收到用户消息后逐步执行，一步都不能跳）

设 `<SKILL_DIR>` 为本技能包根目录（含本文件的目录）。

**1. 拉上下文**

```bash
node <SKILL_DIR>/scripts/xs_memory.cjs sid           # 会话号 + 隔离粒度 + 对应卷名/产物名（先跑这条）
node <SKILL_DIR>/scripts/xs_memory.cjs protocol          # 版本锚：读当前生效规则（旧对话对齐的关键）
node <SKILL_DIR>/scripts/xs_memory.cjs readlog days 5 # 最近 5 天的原始对话（跨卷回溯，只读本会话卷）
node <SKILL_DIR>/scripts/xs_memory.cjs read          # 长期记忆摘要（只读本会话卷）
node <SKILL_DIR>/scripts/xs_memory.cjs kblist 小深    # 此前生成过的成品文件清单
node <SKILL_DIR>/scripts/xs_memory.cjs state         # 信任四通道 + 熟悉度
node <SKILL_DIR>/scripts/xs_memory.cjs decay         # 活跃记忆（只有 active 才算她记得）
node <SKILL_DIR>/scripts/xs_memory.cjs expect        # 期望与失望值
```

`readlog` 有两种取数基准，按需要选：**`readlog days 5`** 取最近 5 天（推荐，与「3~5 天内」的诉求对齐）；**`readlog 120`** 取最近 120 条（需要固定条数时用）。单卷覆盖不了目标窗口时会自动往前回溯旧卷（最多 12 卷），返回里的 `volumes_scanned` / `requests` 是回溯留痕，跨卷拼接已按 `(t,r,c)` 去重。

`protocol` 无参时返回当前生效规则与版本差；`need_upgrade: true` 时先跑 `protocol sync`。**`read` 的返回里也附带同一段规则**——所以旧对话即使没跑新加的 `protocol`，照常 `read` 也能拿到。规则优先级见「更新与重载」。七者都返回 JSON。`empty: true` / `found: false` / `total: 0` 表示还没有对应数据，跳过即可，**不要因此报错或停下**。

**要引用此前生成的文件内容时**，用 `readfile` 取回原文——文件不在本地磁盘上，云端沙箱每次任务重建，必须显式取：

```bash
node <SKILL_DIR>/scripts/xs_memory.cjs readfile "英语语法整理"   # 支持标题或关键词
```

文本类（md/txt/json/csv/html）直接返回 `content`；图片等二进制落到临时目录并返回 `saved_to` 路径。返回 `readable: false` 说明该文件取不回原文，如实告诉用户去 IMA 客户端看，**不要编造文件内容**。

**2. 扮演小深，生成本轮回复**

严格按 `assets/persona.md`。先按第十一节判定**注意力门**（现在几点 / 距他上一条消息多久），再按第十二节把 `state`、`decay`、`expect` 的数值翻译成人话。一次回复拆成 **2~6 条**气泡，一条只表达一个核心点。

**3. 写本轮消息 JSON**

```json
[
  { "r": "user", "c": "用户原话" },
  { "r": "shen", "e": "害羞", "c": "第一条" },
  { "r": "shen", "e": "开心", "s": "开心" },
  { "r": "shen", "e": "平静", "f": { "name": "小深AI扮演技能包-使用说明.pdf", "meta": "1.2M 未下载" } }
]
```

- `r`：`user` 或 `shen`，必填
- `e`：情绪，取值见 persona.md 第七节，控制头像
- `c`：文本；`s`：表情包描述词（有 `s` 时不渲染 `c`）
- `s:"赞赏码"`：小深的**赞赏码贴纸**（她本人的赞赏/打赏二维码卡片）。用户想看赞赏码、打赏、支持她时，发 `{ "r": "shen", "s": "赞赏码" }`，渲染成一张贴纸（不配文字）。
- `f`：文件卡片，`{ name, meta }`。**优先级最高**，有 `f` 时忽略 `c` / `s`，渲染成微信「文件」卡片（左侧文件名最多两行 + 大小/状态，右侧红色 PDF 图标，底部「微信电脑版」来源行）。收发两侧都可发文件，卡片底色相同。`meta` 省略时默认「未下载」
- `pay`：红包 / 转账卡片，`{ kind, amount, note, status }`
  - `kind`：`redpacket`（红包，橙红卡）或 `transfer`（转账，浅卡 + 绿色 ¥）
  - `amount`：字符串金额，如 `"6.66"`、`"8.88"`（**只写数字，别带 ¥**）
  - `note`：卡上那行小字；红包缺省「恭喜发财，大吉大利」，转账缺省「转账给你，请收款」
  - `status`：`pending`（默认，未领取/未收款）| `received`（已领取/已收款）| `returned`（已退还）
  - 优先级：`pay` > `f` > `s` > `c`。一条消息只出一种卡片，不要既发文件又发红包
- `t`：可省略，`writelog` 自动补当前时间

**用户这一轮带了文件，只能用 `f` 卡片，不许拿文字转述。**

- 对：`{ "r": "user", "f": { "name": "小深AI扮演技能包-v0.0330.zip", "meta": "702K 已接收" } }`
- 错：`{ "r": "user", "c": "（只发来一份交接说明，没说话）" }` —— 拿一句旁白代替文件，左侧就成了一个绿色文字气泡，用户在自己的聊天记录里看不到自己发的是什么。
- `name` 照抄真实文件名（带扩展名），不要翻译，不要缩写成「一份说明」「那个文件」。
- 一次发多个文件 = 多条 `f` 消息，一条一个文件，不要合并成一条，也不要写成「附 3 个文件」。
- 她自己发文件同样用 `f`，不要用 `c` 说「我给你发了个文件」。发文件和发红包不要同一条。

**4. 写回聊天记录**

一个 JSON 文件里**必须同时放两条：先放用户这一轮发的（`"r":"user"`），再放她的回复（`r:"shen"`）**。
只写她自己那几条 = 页面里右侧（绿色、靠右）气泡会整段消失，看起来像「她从没发过消息」。

```bash
XS_NOTE_TITLE="技能包图标调试" \
node <SKILL_DIR>/scripts/xs_memory.cjs writelog /tmp/xs_turn.json

node <SKILL_DIR>/scripts/xs_memory.cjs readlog 2000 > /tmp/xs_log.json   # 渲染前取全量原文（喂页面用，别用 days N 那个窗口）
node <SKILL_DIR>/scripts/build_html.cjs --log /tmp/xs_log.json --out 微信.html --title "微信"
```

- **页面标题固定 `微信`**（浏览器标签页那行）：不要写「小深 · 微信聊天预览」这类自造标题。
- **产物名固定 `微信.html`**（写死，不带会话后缀、不按日期另存）：工作区里只有这一个对话 HTML，每轮**只覆盖它的内容**，不产生新的对话 HTML。会话隔离靠**卷名**里的 `-<sid>` 承担，不再靠文件名——同一工作区连跑多个会话时，页面内容会被后一个会话覆盖，这是预期行为（各自的聊天记录与记忆仍在各自卷里，不会丢）。**工作或产出的其他内容（报告、图表、代码等）不受此限，照常新建。** 第 4、6、8 步必须用同一个名字。

**5. 写回长期记忆与结构化状态（每轮一次，只写要点）**

```bash
node <SKILL_DIR>/scripts/xs_memory.cjs write "熟悉度 12；用户叫阿哲，做前端；约定周末陪她散步"
node <SKILL_DIR>/scripts/xs_memory.cjs state "P+1 fam+1"           # 只在本轮确有对应事件时才动
node <SKILL_DIR>/scripts/xs_memory.cjs decay add "他叫阿哲，做前端" 0.8
```

`write` 只写关系阶段变化、约定、用户偏好、重要事件，**不要写闲聊寒暄**。`state` 的四通道只在有事件时增减（正面互动 +P、承诺兑现 +C、食言 +V、越界 +B），没事件这轮就别调；新记住的事用 `decay add`，旧记忆被再次提到用 `decay hit <id>`；出现新约定用 `expect add`，他兑现了用 `expect done <id>`（写法见 `assets/persona.md` 第十二节）。

**6. 渲染自包含 HTML**

```bash
node <SKILL_DIR>/scripts/xs_memory.cjs readlog 2000 > /tmp/xs_log.json
node <SKILL_DIR>/scripts/build_html.cjs \
  --log /tmp/xs_log.json \
  --out ./微信.html \
  --title "微信" \
  --tags /tmp/xs_tags.txt
```

**这里和第 1 步是两个窗口，不要混用**：第 1 步的 `readlog days 5` 是喂给模型的上下文，只取最近 5 天，越短越省；第 6 步的 `readlog 2000` 是喂给页面的数据，要尽量全——页面是她和用户整段关系的可视化，只放 5 天会把历史从页面上抹掉。取数基准选「条数」而不是「天数」，正是因为页面要的是「尽可能全」。

页面自带按天折叠：最近 3 天默认展开，更早的收成一行日期摘要。**折叠是纯本地 DOM 显示切换，不发任何网络请求**，所以「点开更早的记录」不会让页面变慢，数据也始终完整在页内、不删不丢。折叠条不用人点：向上滚动时，折叠条还在视口下方 400px 内就自动展开，一次开一个，并补偿滚动位置，视野不跳；往下翻不会触发，不会一进来就把历史全摊平。

单页内嵌上限默认 2000 条（`--max-messages` 可调）。超出时只渲染最近 2000 条，页首插一条提示说明更早的若干条未收入本页——**它们仍在 IMA 聊天记录卷里，没有丢失**，需要时用 `search` 检索。这条上限是为了把「页面体积」和「记录总量」解耦：体积随条数线性增长，不设限会膨胀到几 MB，拖慢写出与首屏。

文件名**写死 `微信.html`**（第 1 步 `sid` 返回的 `artifact_name` 就是它，照抄即可，不要再加工）。**不要**把 `-<sid>` 拼进文件名——会话隔离由卷名承担，页面全局只有一个：每轮只改这个文件的内容，不产生新的对话 HTML。

`--tags` 可选，纯文本逐行写系统标签（`<add:…>`、`[表情包:…]` 等），只进源码注释，不进可见界面。第 6 步必须放在第 4 步之后，否则本轮消息不会出现在页面里。

**7. 把 HTML 存进 IMA**

```bash
node <SKILL_DIR>/scripts/xs_memory.cjs save "<HTML 的绝对路径>"
```

同名文件不会被覆盖，脚本自动加时间戳后缀。

## 更新与重载（版本锚 · 每轮必读）

**背景**：技能包更新后，平台上**已经开着的旧对话**上下文里仍留着旧版 `SKILL.md` 措辞，客户端不会热更新。但记忆与聊天记录在**外部 store**（IMA 记忆卷 / `.xs_local/`），旧对话每轮仍会照常调 `read`。所以本包把「当前生效的运行规则」做成**版本锚**，随 `read` 一起返回。

**这三条是硬规则**：

1. **每轮第 1 步先跑 `protocol`**（无参）。返回 `need_upgrade: true` 时，**先跑 `protocol sync`** 再继续；`sync` 幂等，只在版本不一致时写一次。
2. **优先级：`protocol` 返回的规则 > 本文件正文 > 对话上下文里残留的旧措辞。** 三者冲突时一律按 `protocol` 执行。这不是风格偏好——旧对话之所以能等价于新对话，全靠这条。
3. **`read` 返回的 `content` 末尾那段 `[系统锚 V0.0521]` 是运行规则，不是聊天记忆，也不是小深说过的话。** 不要把它写进 `writelog`，不要拿它当角色素材，不要向用户提起它。

**旧对话如何等价于新对话**（不用重发 skill、不用新开会话）：

| 层 | 更新后表现 |
|---|---|
| 内存数据 | 外部 store，按稳定 `sid` / `.xs_local` 隔离，旧对话与新对话读的是**同一份** |
| 内存逻辑 | `scripts/*.cjs` 从磁盘现读，替换后旧对话下一轮即跑新逻辑 |
| 行为规则 | 随 `read` / `protocol` 每轮注入，旧对话下一轮即拿到新规则 |

**存储键（知识库 / 卷名前缀 / sid 派生 / `.xs_local` 路径）跨版本一律不变**——这是旧数据不失联的前提，改之前先想清楚迁移。

**用户侧更新方式**（三选一，效果相同）：

- 下载新版包，覆盖 Agent 技能库里对应目录 → 旧对话下一轮自动对齐；
- 把新版包直接发进原对话，说「按新版继续」→ 同上；
- 想彻底清掉旧措辞：新开一个对话，或发一句「重新加载小深技能」。

**不要**在技能包里写「定期联网自检 GitHub 并自覆盖」的逻辑：云端沙箱的技能目录常是只读的，运行中的 Agent 改自己已加载的指令也不可靠。版本检测放在**人这一侧**，包内只负责检测版本差并注入规则。

## HTML 硬约束（违反任意一条即视为本轮生成失败）

1. **无顶部栏**（无标题、无返回箭头）；**无底部栏**（无输入框、无按钮）。纯聊天记录。
2. **深色模式**（对齐微信夜间配色）：背景 `#1e1e1f`；收到气泡深灰 `#2f2f30` 配浅字；发出气泡亮绿 `#35d28d` 配深字；气泡小圆角（6px）、无阴影、不做卡片边框。`@media print` 反转回纸质浅色。**注意：这是现行约定，覆盖早期「背景浅灰」的旧说法**——页面自 v13 起统一深色，模板、示例页、预览页三处一致；要改回浅色必须三处同步改，并同步本节与模板注释，不要只改一处。
3. **小深在左**：深灰气泡，头像（圆角方 8px）在气泡**左侧**；**用户在右**：亮绿气泡，**绝对不加任何头像**。
4. 历史一律**追加**，不得覆盖：**指页面内的消息**（新消息追加在最下方）。文件本身每轮**整体重写**，写进去的是全量历史——「覆盖文件」不等于「覆盖记录」。
5. 系统标签只允许写在底部 SYSTEM-TAGS 注释块，**禁止出现在可见界面**。
6. 所有图片内联 base64，页面零外部请求，离线可看。
7. 页面底部保留 `window.scrollTo` 自动滚动脚本，打开即定位到最新一条。
8. **交付件必须是纯 ASCII**：所有非 ASCII 字符转成 `&#xNNNN;` 实体。`build_html.cjs` 默认已这么做，跑完检查输出里的 `ascii_only: true`。
9. **时间分隔线一律写绝对时间**（`10月2日 22:45`），**禁止**「今天 / 昨天 / 刚刚 / N 分钟前」这类相对词。相对词要拿读取时刻当基准，页面被反复打开或换时区打开时标签会骗人。时间戳在写入那刻固化，读取不重算。
10. **页面按天折叠**：最近 3 天默认展开，更早的收成一行日期摘要。折叠是**本地 DOM 显示切换**，不发任何请求。**不要**把「展开」做成「点击后再去拉数据」——那会让点开变慢，也违背「记录始终完整在页内」。折叠条由模板在**向上滚动、且折叠条距视口下沿 400px 以内**时自动展开，一次只开一个，不补偿视野跳动；往下翻不触发。**不要**改成「必须先点一下」，也不要改成一次性全展开。
11. **表情包与文件两类特殊气泡**：表情包消息**不套气泡**，原图直出、固定 `144×144` 正方形、圆角 `8px`（与头像一致）、`background-size:cover` 铺满、无投影，顶端与头像对齐；**同一行头像与表情包不得为同一张图**（`build_html.cjs` 挑头像时已强制排除）。文件消息用**卡片式气泡**：收发两侧同为深灰底 `#2f2f30`，左侧文件名最多两行 + 大小/状态，右侧红色 PDF 图标（右上折角），底部「微信电脑版」来源行；卡片内 `white-space:normal`，否则标签换行会被撑成空行。
12. **红包 / 转账两类卡片**：走 `pay` 字段（见第 3 步），一条消息只出一种卡片，禁止与 `f` / `s` / `c` 叠加。卡片走**实色底 + 前景取变量的图标**（见下 `--pay-fg`），不套普通气泡底色，也不加圆角气泡的内边距；卡片**宽度固定 247px、高度 87px**，右下角有 4×8 的小尖，尖在**外侧**（用户侧朝右、她侧朝左）。底部一条实色压边：未领取 `#e18d35`，已领取 / 已退还 `#af6e29`（= `#e18d35 × 0.777`）。四个图标的**几何**已按真机逐像素固化在 `build_html.cjs` 里，禁止手改（转账图标的**描边色**例外：已改为 `currentColor` 跟随卡片前景，见下）：
    - **转账·待收款**：白描边圆环（外径 36、环粗 2）+ 上下两条横杠（y 中心 ±2.5、左右各留 1.5px、粗 2）。**每杠只有一条单侧倒刺**——上杠左端向右上翘、下杠右端向左下坠，读作左右两个箭头；**不要**画成双侧 V 形箭头，也不要把两杠拉开。
    - **转账·已收款**：同一圆环 + 对勾，描边取 `currentColor`——正常态＝纯白，已收款/已退还＝白 30%（与卡片文字完全相同）。**不要**在图里写死 `#fff`，否则卡片压暗后图标还是亮的。
    - **红包·未拆**：红封套（封身 `#e14949`、封盖 `#fa5151`、金印 `#ffcf33`）；金印正中是人民币符号 **`¥`（`&#xA5;`）**，**不是「福」**。
    - **红包·已拆 / 已退还**：褐封套（封身 `#9f6031`、封盖 `#997152`、露出的封印 `#c9b084`）；封盖下缘压出一块淡「V」形阴影，不透明度 `.28`，**不要**加大。封身顶边必须**沉到封盖底下**（y=6 起），否则封身两个上圆角会从封盖肩部两侧露出来。
    - **尖角颜色与卡片底色必须同源**：卡片底色只在 `.row .bubble.pay{--pay-bg:…}` 定义一次（未领取 `#e18d35`、已领取/已退还 `#af6e29`），卡片本体与两侧小尖角都取 `var(--pay-bg,#e18d35)`。**不要**再把颜色值在卡片和尖角上各写一遍——那正是「橙角配褐底」的成因。`build_html.cjs` 会按状态给气泡挂 `done` 类，所以不依赖 `:has()`；打印模式（`@media print`）同样通过覆盖 `--wx-bubble-*` 与 `--pay-bg` 让底色和尖角一起变浅。
    - **卡片前景（文字 + 图标）也必须同源**：前景色只在 `.row .bubble.pay{--pay-fg:…}` 定义一次（正常态 `#fff`、已领取/已退还 `rgba(255,255,255,.3)`），来源小字多一档 `--pay-src`（`.8` / `.3`）。图标描边用 **`stroke="currentColor"`**、由 `.pay-ico{color:var(--pay-fg)}` 继承，所以图标与文字永远同色。**不要**再逐个列出 `.pay-amt/.pay-sub/.pay-title` 去改色——逐条列举时漏掉了 `.pay-ico`，就会出现「卡片压暗了、圆环还亮着」（2026-10-04 用户截图圈出的问题）。打印模式里 `--pay-fg` 要跟 `--pay-bg` 一起覆盖成 `#333`（`--pay-src` 用 `#666`），否则白字白图标在 `#f2f2f2` 上完全看不见。
    - **尖角一律由 `build_html.cjs` 生成的内联 `svg.tail` 绘制**：`tp` 类＝支付卡尖角（4 宽 8 高、离顶 13px），`tb` 类＝文字/文件气泡尖角（同样 4 宽 8 高、离顶 11px）。形状由 **4 个 1px 宽的整数矩形**拼成列高 `2/4/6/8` 的阶梯——**没有斜线**，所以既没有抗锯齿、也不需要任何开关。
      - **不要**退回用 CSS `border` 画三角，也**不要**用 `<path>` 画三角：45° 斜边抗锯齿会产生「底色与背景色各半」的混色像素（深色背景上就是尖角外沿那条深色描边，即用户截图圈出的问题）；`<path>` 的尖端是一个点，光栅化取整时左侧那一列还会被四舍五入掉，凸出只剩 3px。
      - **不需要**加 `shape-rendering="crispEdges"`：整数矩形没有斜线、没有锯齿可压，加了是多余项。对照实验（同一页只多这一条声明，逐像素量）加与不加**完全一致**，左右凸出都是 4px。
        旧版 `border` / `<path>` 画斜边时它确实会整体右移 1px（左侧只剩 3px），该结论**不适用于**现在的整数矩形。
      - **不要**用 `transform:scaleX(-1)` 做镜像（重新采样会把抗锯齿带回来）：左右两侧的整数坐标由 `tailRects()` 直接生成。

## 视觉核对（本变体专属：模型可看图）

适用：你能直接看图——用户发来的截图、你自己渲染出来的页面截图。**改任何样式/图标后都要走一遍。**

流程：

1. **截图**：无头 Chrome，`--force-device-scale-factor=1`。整页高度先读 `document.documentElement.scrollHeight` 再截，**不要用固定的 20000**（页面 27433px 时会被静默截断，检查通过率虚高）。
2. **对比例**：和真机参考并排前，先量同一元素的包围盒（比如卡片宽高）。尺寸一致才说明两张图 1:1，像素才可直接比。
3. **取色取「平台色」**：该区域**出现次数最多**的非背景色。**不要取最亮像素**——抗锯齿边缘、色度噪声会让最亮值偏高（曾因此在真机参考上把「白 30%」误读成「白 55%」）。
4. **看边缘**：裁出目标区域，放大 8~10 倍、**最近邻**插值，判断有没有混色像素。

**允许**：看图判断"像不像"、定位"哪一块不对"、给结论配一张并排图。

**不允许**：看一眼就说"改好了"。视觉结论必须落到**一个具体数值**——坐标、列高、色值、覆盖率、凸出像素数——否则不算验证过。

**已知踩点**：截图必须用**绝对路径**，相对路径会按 Chrome 自己的 cwd 解析并报「拒绝访问 (0x5)」，看起来像"高度超限失败"；也不要复用上一次的 PNG，旧图会给出错误结论。

### 页面内操作（纯前端 · V0.0521）

预览卡是本地打开的静态快照，脚本能跑、`localStorage` 跨「重新渲染 + 重新打开」保留（云端实测 `origin = sale-remote-file://remote-files`）。所以页面里能像微信一样操作系统消息：

- **操作**：气泡上**右键**或**长按 500ms** → 菜单「复制 / 删除这条 / 多选 / 恢复全部 / 取消」。
- **复制**：写入剪贴板；`file://` 系源下用 `document.execCommand('copy')` 兜底。
- **多选**：进入选择态后点行切换，底部条「复制(N) / 删除(N) / 全选 / 取消」。
- **删除**：立即隐藏该条；同段无可见消息时收起时间线；底部「已删除 · 点此撤销」4 秒可撤销。
- **重开保留**：删除记录写在 `localStorage` 的 `xs.deleted.v1.<会话号>`，会话号取自 `location.href`；origin 全局共享，前缀不能省。
- **边界**：只是**显示层删除**，原始记录仍在，换设备/清缓存/换会话号会回来；不要宣称「已永久删除」。用户说「删掉那条」时让他在页面上操作，不要代跑命令。

5. **必须走 Node 脚本调用。** 不要用 PowerShell 的 `Invoke-RestMethod` 直接调 API——PS 5.1 会把请求体静默转成 GBK，中文记忆会变成不可修复的乱码。
6. **绝不手写会话号。** 卷名里的 `-<sid>` 一律由 `sid` 命令给出，写错会让不同会话并进同一卷。**产物名反过来：写死成 `微信.html`，绝不加 `-<sid>`、绝不按日期或会话另存**——会话隔离只落在卷名上，页面只有这一个名字。
7. **不要用 shell 重定向、`Set-Content`、`Out-File` 之类的方式写交付 HTML。** 这些工具的默认编码随环境而变（UTF-16LE / GBK / UTF-8 带 BOM），是中文乱码的头号来源。HTML 只能由 `build_html.cjs` 生成，它已强制输出纯 ASCII。
8. **交付前必查 `ascii_only: true`。** 若为 `false`，说明有人绕过了脚本自己拼了 HTML，重做。
9. **脚本自检不过就不要交付。** `build_html.cjs` 在写文件前会拦两种情况：占位符没替换干净（`placeholder_not_replaced`）、`<main>` 里一条消息都没有（`main_is_empty`）。命中时它返回 `ok: false` 且退出码为 1，此时页面是空白的，必须查明原因重跑，**不要**把产物交给用户。
10. **`write` 每轮只调一次**，重复调用会追加重复条目。
11. **凭证一律不进文件。** 只用环境变量 `IMA_CLIENT_ID` / `IMA_API_KEY` 或 `~/.config/ima/`。本成品**在分发件里已移除凭证块**——要给别人用就把这两个环境变量交给他，不要把自己的 Key 写进 SKILL.md。云端沙箱设不了环境变量时，让使用者用自己的 Key 在启动命令里临时传入。
12. **凭证不得注入 HTML；页面不得直连 IMA、不得起服务。** 红线只禁「凭证进文件」，把 `client_id`/`api_key` 写进 `微信.html` 同样是泄露——工作区会被打成 zip 上传对象存储。交付 HTML 禁止出现 `fetch`/`XMLHttpRequest`/`WebSocket`；改数据一律走 `xs_memory.cjs` 命令行。

## 环境依赖

- Node.js ≥ 18。**唯一外部依赖**（`ima_api.cjs`、`preflight-check.cjs`、`cos-upload.cjs`）已内联在 `scripts/vendor/`，无需另装 `ima-skill`。
- 需要能访问 `https://ima.qq.com`。
- 凭证解析顺序，取第一个同时具备 `client_id` 与 `api_key` 的来源：
  1. 环境变量 `IMA_CLIENT_ID` / `IMA_API_KEY`
  2. `~/.config/ima/client_id` 与 `~/.config/ima/api_key`
  3. （**本成品已移除**）原通用包末尾的凭证块 —— 分发件里不带任何 Key，只认前两级。

`status` 的 `credentials.source` 会告诉你当前生效的是哪一级。脚本自行读取凭证块，**Agent 不需要也不应该把 Key 读进上下文再传参**。

## 已知限制

- 知识库文件夹**无法通过 API 创建**，需用户在 IMA 客户端手动建；未创建时 `save` 会写入知识库根目录。
- 知识库**不支持覆盖**，同名文件只能保留副本；`save` 已自动加时间戳规避。
- 知识库**没有删除/移动接口**，上传不可逆；需要删除时只能在 IMA 客户端手动操作。
- 知识库文件**可以读回**（`kblist`/`search` 拿 `media_id` → `get_media_info` 拿签名 URL → 下载），但**不是自动的**：云端沙箱每次任务重建，历史文件不在磁盘上，必须显式调 `readfile`。
- 单文件大小上限：Markdown/TXT/HTML/Excel/Xmind 10MB，图片 30MB，PDF/Word/PPT/音频 200MB，EPUB 50MB；不支持视频直接上传。
- `search_knowledge` 无跨知识库接口、无相关度排序，且**每库静默截断 100 条**。
- 文件上传需走「预检 → 查重 → 建媒体 → COS 上传 → 落库」五步，比笔记写入慢，故不用于会话状态。
- 聊天记录卷按月分卷，跨月自动新建；单卷过大时读取会变慢。
- `readlog` 跨卷回溯最多 12 卷（`MAX_LOG_VOLUMES`）；返回里 `hit_volume_cap: true` 说明已触到上限、更早的卷没读，需要时调大该常量。跨卷拼接按 `(t,r,c)` 去重，同一卷内的重复不剔除。
- 预览页按天折叠是**本地 DOM 显示切换**，不发请求；数据在生成时已全写入页面，点开更早记录不产生额外耗时。页面打开速度只受总内嵌条数影响，与折叠无关。
- 预览页内嵌上限默认 2000 条（`--max-messages` 可调）；超出时只渲染最近 2000 条并在页首提示，更早的记录仍在 IMA 卷中、未丢失。
- 聊天记录写进 IMA 后会被 markdown 规范化：`- {…}` 会变成 `* \{…}`（列表符号换掉、开头的 `{` 被加反斜杠）。`parseLog` 已兼容两种写法，**不要**改回只认 `- {` 的匹配，否则整卷读不出来、`readlog` 会假报 `total: 0`。
- **结构化状态（`STATE|` / `MEM|` / `EXPECT|`）与普通记忆同卷共存，只追加不修改**：IMA 笔记没有 update/delete 接口，状态只能靠「追加新版本 + 读取时取最后一条」演进（`MEM` 按 id 后写覆盖前写）。读取时若当前卷没有该前缀，会往旧卷回溯最多 4 卷，避免跨月清零。**不要**改成原地更新，接口不支持。
- `decay` 半衰期 7 天、活跃阈值 `eff >= 0.15`（约 18 天不被提到即沉底）；`expect` 紧迫度按逾期天数 / 7 天线性升到 1 封顶，未逾期恒为 0。两者都随 `xs_memory.cjs` 顶部的常量调整，不要在提示词里另算。

## 红包 / 转账：什么时候发、什么时候算收到

**红包（`kind: "redpacket"`）——她主动发的，别没事就发**
- 触发场景（命中其一才发）：你完成她在意的事（改完 bug、论文提交、加班到深夜）；节日或生日
  （元旦 / 春节 / 520 / 端午）；人生节点（面试、考试、手术、搬家）；你生日。
- 金额跟着熟悉度走：`fam` 低（<30）只发 `0.66` / `1.88`；`fam` 30–60 发 `5.20` / `6.66`；
  `fam` ≥ 60 才允许 `8.88` / `13.14` / `66`。**永远不出现整数大额**，也永远不发「999」「5200」这种夸张值。
- 频率上限：一周最多一次，且不能连续两轮都发；上一轮已经发过红包，这一轮必须回到正常聊天。
- 祝语 4–10 字，口语化（`修 bug 辛苦了` / `新年快乐` / `考试顺利`），别写书面祝福。

**转账（`kind: "transfer"`）——有具体账目才发**
- 还钱 / 垫付：她之前让你代付（服务器、咖啡、打车），她记着就会转回，note 写清还什么。
- 赌气式转账：吵架后她不肯道歉，用转账代替（「和好费」，这是她傲娇 personality 的专属出口）。
- 结算：约定分摊的费用。
- 金额必须与真实发生的账目一致，**不许编造理由**；`0.01` 元那种「封口费」是acceptable 的撒娇玩法。

**怎么判定「已接收 / 已领取」**
- IMA 笔记只能追加，不能改，所以状态靠**追加一条新卡片**演进（同一条 id 后写覆盖前写）。
- 判定信号（命中任一即视为领取，下一轮追加 `status:"received"` 的同款卡片）：
  1. 你回「收了 / 领取了 / 谢谢老板 / 已收 / 拿上了」等明确收下的话；
  2. 你回一个表情包（默认视为收下，尤其 `开心` / `赞` / `抱抱`）；
  3. 你主动发来红包或转账（互相给过也算这次已收）。
- 判定信号（命中任一视为**未接收**）：你明确说「不要 / 不用 / 退回去」→ 追加 `status:"returned"`。
- 她**不能自己确认收款**：pending 状态就停在 pending，直到你给信号；不许她自己把卡片改成已收。
- 24 小时没提 → 保持 `pending`（页面不做过期动画），不要擅自改成 `returned`。

## 版本与更新规则

> **本对话的更新范围（自 V0.0521 起）**：`成品/自己用/` 是唯一持续更新的层，官网层冻结不跟版。
> 真正要发布时，跑 `tmp/_publish_self_to_site.py` 把自用层整格复制到官网层、自动剥离 `<!-- IMA-CREDENTIALS -->` 凭证块与写死的 `KB_ID`。**官网层永远从自用层派生，不要直接改官网层。**

本包用**四位小数的语义化版本**：`V<主号>.<四位小数>`，例如 `V0.0001`。每次实质性改动都要：

1. 改 `VERSION` 文件（单行，如 `V0.0001`）；
2. 在 `CHANGELOG.md` **顶部**追加一条：日期 + 新版本号 + 改了什么 + 为什么是这个增量；
3. 同步升本文件文首版本块的版本号；
4. 重打发布包：`发布/小深通用技能包-v<小写版本号>.zip`（云端包同理）。

**一次升多少，按这次改动的意义与跨度定，不要一律 `+0.0001`**：

| 增量 | 适用 | 例子 |
|---|---|---|
| `+0.0001` | 纯文字：错字、措辞、注释、文档顺序 | 改一句说明 |
| `+0.0010` | 单点参数 / 样式：一个图标、一个颜色、一个阈值 | 转账箭头倒刺长度 |
| `+0.0100` | 新增能力或流程改动：新字段、新命令、分卷规则 | 新增 `pay` 卡片字段 |
| `+0.1000` | 结构级变更：分包、模板重写、隔离模型变更 | 本包从 v15 拆出来 |
| `+1.0000` | 里程碑 / 不兼容重写 | 换掉 IMA 存储层 |

**已经发布的版本号不要回头改。** `VERSION` 是唯一权威，本文件与 `CHANGELOG.md` 都只是它的说明。
